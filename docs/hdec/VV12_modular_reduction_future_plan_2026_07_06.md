# VV12 后续计划：斜线级边算边模

## 当前状态

VV12 基线采用 practiceB15：

- 多项式模乘的两条斜线计算路线已经进入统一位矩阵行包。
- AND + popcount 路线用于一部分斜线奇偶归约。
- AND + row-XOR 路线用于另一部分斜线奇偶归约。
- 直接模折叠贡献已经整理成 4x64 位贡献包，并通过 XOR0 完成 GF(2) 累加。
- 当前模约减粒度是 leaf/word 级直接模折叠，不是完整 466-bit 后置模约减。

## 当前模约减流程

```text
斜线计算
→ leaf 局部乘积
→ Karatsuba / word 级组合
→ 生成直接模折叠贡献包
→ XOR0 累加到 233-bit 域结果
```

这条路线已经避免了完整乘积暂存，并把最终 GF(2) 累加放入共享位贡献包路径。

## 最终目标

后续若继续深化模约减，目标是把 leaf/word 级直接模折叠推进到斜线级边算边模：

```text
斜线奇偶 bit
→ 根据指数 k=i+j 判断最终域坐标
→ 直接生成位贡献包
→ XOR0 累加到 233-bit 域结果
```

## 数学规则

不可约多项式：

```text
f(x) = x^233 + x^74 + 1
```

因此：

```text
x^233 = x^74 + 1
```

若斜线指数为 `k`：

- `k < 233`：直接落到第 `k` 位。
- `233 <= k < 392`：折叠到 `k-233` 和 `k-159` 两个位置。
- `392 <= k <= 464`：需要二次折叠，落到 `k-233`、`k-318` 和 `k-392` 等位置。

## 硬件原则

- 不恢复完整 466-bit 乘积暂存。
- 不使用动态大索引 `result[dynamic_index] ^= bit`。
- 使用固定 group、固定连线、小表映射生成位贡献包。
- 贡献包继续通过 XOR0 累加，不新增 ECC 专属大 XOR 网络。
- 只有在 Logic LUT 仍可控制在 VV12 门槛内时才合入。

## 暂不执行原因

当前 VV12 已经具备较完整的论文故事：

```text
统一位矩阵行包
→ 共享 AND
→ 共享 popcount / row-XOR 奇偶归约
→ 贡献包直接模折叠
→ XOR0 GF(2) 累加
```

斜线级边算边模属于下一阶段深化，不应在 VV12 基线建立前混入，以免同时改变斜线计算和模约减两个变量。
