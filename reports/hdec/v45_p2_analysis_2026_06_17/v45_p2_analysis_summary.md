# V45 P2 控制实验小结

日期：2026-06-17

## 当前保留版本

当前 RTL 保留的是 `P1 reg remove` 版本：

- P1 不再保存完整 uop，P0 在两次 VRF 读之间继续持有同一个 uop。
- P2 仍然保存完整 uop，继续作为 lane 计算和 P3 写回之间的隔离点。
- 点乘周期不变：183793 cycles。
- OOC 时序仍满足 200 MHz：WNS 0.247 ns，估算 Fmax 210.393 MHz。

这版和 `P1-only` 综合结果完全一致，但源码更干净，能说明算法上只有单个活动 token，不需要 P1 再复制一份 uop。

## 为什么 P2 不能直接删

P2 不是单纯的“多余寄存器”。它有三个实际作用：

1. 把 P0 的读地址/下一条 uop 生成，和 lane 的计算模式隔开。
2. 把 lane 计算结果和 P3 的 VRF 写回控制隔开。
3. 让 `uop_p2_q.valid` 作为一拍有效标签，限制哪些计算锥真正活跃。

全删 P2 后，`uop_p0_q` 会同时驱动两大块逻辑：一边是下一轮读地址和控制跳转，一边是 lane 计算模式。结果是 FF 少了，但顶层和 VRF 的 mux 变大，LUT 反而增加。

## 三个 P2 试验的结论

### 1. P2 mode tag

思路：保留完整 P2，同时额外寄存几个 1-bit 模式标签，让 lane 不再重复比较 `op_type`。

结果：lane 小了一点，但顶层和 VRF 变大，总 LUT 从 6037 增到 6095。

原因：新增 tag 本身又进入全局控制和写回选择，等于多了一组控制 mux。

### 2. P2 narrow token

思路：P2 只保留 lane 需要的 `valid/op/subgroup/perm`，完整 uop 提前放到 P3。

结果：FF 从 1968 降到 1949，但 LUT 从 6037 增到 6059。

原因：完整 uop 提前进 P3 后，P3 写回/地址控制的输入选择变复杂，VRF 层次 LUT 从 3486 增到 3522。

### 3. P2 valid elide

思路：`p2_lane_compute_q` 已由 `uop_p2_q.valid` 生成，于是去掉 lane 计算条件里的重复 valid。

结果：LUT 大幅增到 6330，F7 mux 从 48 增到 310。

原因：这个 valid 不是“无用重复”，它帮助综合器约束活跃计算锥。删掉后，Vivado 把更多共享 mux 展开到 P3/HMATCH 和 VRF 相关路径。

## 结论

P2 增面积的根因不是 P2 这个寄存器本身，而是删掉或重排 P2 后，控制 token 会跨越更多全局逻辑，导致 VRF 写回和 P3 控制 mux 放大。

所以目前更好的方向是：

- 保留 P2 作为隔离点。
- 不再尝试全删 P2。
- 不把完整 uop 提前塞进 P3。
- 继续从算法级减少进入 P2/P3 的 uop 次数，或者减少 P3 写回分支，而不是压缩 P2 本身。

当前可接受收益相对 V44 U：

- Slice LUT：6132 -> 6037，减少 95。
- Logic LUT：5660 -> 5565，减少 95。
- FF：2008 -> 1968，减少 40。
- 周期：183793，不变。
- 时序：210.393 MHz，不变。
